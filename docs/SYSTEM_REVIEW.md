# System review

**Reviewed:** 24 November 2026
**Scope:** repository, product flows, automated tests/build, production HTTP and MCP behavior, and recent Vercel runtime error clusters.  
**Status:** active review snapshot; this is not a security certification or a claim that every roadmap item is complete.

## Current assessment

The core interview lifecycle is in good shape for bounded, host-run questionnaire collection. The app validates questionnaires, isolates respondent links, retains recoverable drafts, supports routing and repeat records, separates respondent-level analytics from repeat rows, offers multiple export formats, and protects MCP operations with credential-scoped capabilities. The automated suite and production build are healthy.

The largest remaining risks are operational durability and scale: outbound mail can have an ambiguous result after a provider accepts it, individual respondent payloads can grow with questionnaire size, and several export formats remain in-memory and capped. Governance features are also host-dependent: consent notices, retention, withdrawal, and deletion schedules are not first-class workflows. The new questionnaire composer covers common scalar and repeat-group authoring and bounded AND routing; stable-ID editing of existing versions, OR routing, and scheduled campaign tools remain meaningful adoption improvements.

## Shipped during this review

The following changes are pushed to `main` and deployed:

- Oversized respondent saves preserve the last valid draft.
- MCP request and schema validation reject malformed, oversized, hostile-origin, and unsupported requests.
- Repeat records are present in Excel/JSON and readable Markdown exports; CSV omissions remain disclosed.
- Relay-based DSN results remain unconfirmed rather than being reported as delivered.
- Respondent deletion removes associated mail history transactionally.
- Asset deletion now checks the confirmed name and public ID at the atomic delete, preventing a concurrent rename from defeating confirmation.
- Invite sends, workspace invites, and delivery checks have atomic per-person/recipient/workspace limits and fail closed when the rate-limit store is unavailable.
- IMAP checks and logout cleanup have bounded deadlines; timeouts retain the existing `unknown` result.
- Authentication distinguishes invalid/revoked sessions (401) from account-store outages (503 on API/frame routes).
- Audit event write failures produce sanitized operational logs, and unknown MCP tool attempts enter the audit path.
- Participant invite attempts are durably recorded as pending before SMTP; ambiguous outcomes block ordinary retries, an on-demand IMAP check can resolve a matching delivery-status notice, and explicit resend warns of possible duplicates.
- Active workspace invitation links no longer rotate on repeated requests or concurrent sends; SMTP ambiguity leaves the invitation active, with revoke-before-replacement behavior shown in settings.
- Workspace invitation attempts persist their exact Message-ID before SMTP; hosts can check that id for delivery-status evidence with per-invitation and workspace throttles.
- The host People list, host Answers matrix, and MCP people/status/mail-status reads paginate in bounded cursor pages. MCP interview-wide answer reads page through bounded 50-row results (maximum 100) and apply `submittedOnly` in the database query; buffered host and MCP export formats cap cohorts at 100. Targeted MCP answer reads load one tenant-scoped person.
- A rejected cold-start Mongo connection now clears only its own cached promise so a warm worker can retry when the database recovers.
- Published questionnaire assets and asset deletion now share a transactional coordination point; a concurrent deletion cannot leave a newly published version pointing at a missing image.
- Preview-draft saves now touch referenced assets in a transaction, coordinating draft creation and reclamation with asset deletion.
- Respondent deletion now erases linked activity events and stale analytics runs, including legacy event/mail rows without a tenant field. Deletion, invitee additions, and reopening submitted answers increment the respondent revision in their transaction.
- Paged analytics cache creation now fences against concurrent respondent writes and questionnaire publication. A stale scan returns `analysis_run_stale` rather than caching results after a conflicting change.
- Public accessibility auditing now checks for an `h1` in each questionnaire document while allowing the respondent shell to identify its embedded questionnaire through the iframe title.
- Public respondent load, frame, save, and submit APIs now have separate hashed per-link and per-Vercel-IP rate limits; an unavailable shared limiter fails closed with 503.
- Host Overview and People pages now retain progress counts but omit answer, repeat-record, and order-history payloads; assignment history is not queried until the Answers tab loads.
- The host Answers matrix now pages through respondents using the same bounded cursor contract as the People list.
- Settings now shows tenant-scoped workspace image use against a transactional 100 MiB cap. Upload and delete mutations serialize through the tenant record so concurrent uploads cannot exceed the limit; existing over-limit workspaces can delete assets and upload again after falling below the cap.
- Adding more than 100 people in one request is now rejected atomically at the host API and MCP boundaries. The host dialog no longer truncates oversized pasted lists silently and directs hosts to split them into batches.
- Questionnaire publication guidance labels its answer count as the first loaded respondent page, avoiding an implied interview-wide total for larger interviews.
- Host CSV-wide and CSV-long downloads use a stable newest-first creation order at every cohort size; files above 100 people stream through bounded 10-person cursor pages. The host keeps buffered JSON, Markdown and Excel downloads capped at 100 people.
- Buffered host and MCP exports now check the cohort’s aggregate BSON size before answer documents are hydrated and reject payloads above 8 MiB with a typed limit response; streamed host CSV remains available for larger cohorts.
- Buffered export responses are capped at 16 MiB after generation, MCP avoids repeating text payloads above 64 KiB, and streamed host CSV stops after 64 MiB. Streamed participant pages also enforce the 8 MiB BSON source budget. These caps bound responses, but buffered serializers can still peak above their response size while generating an artifact.
- The owner-only Axion tenant backfill now uses an expiring cross-invocation lease, records per-collection update checkpoints, exposes the latest progress in Settings, and remains safe to retry after an interrupted collection update.
- Tenant migration preflight now runs after lease acquisition, so concurrent authorized calls do not all scan the same legacy collections. Interview deletion now also cascades temporary questionnaire-review drafts.
- Save, submit, reopen, and first-open respondent events now commit with their participant writes, so erasure cannot race a late audit insert. A respondent write epoch rejects saves and submissions from tabs opened before a submit/reopen transition.
- Rejected questionnaire replacements now clear the previously accepted upload state, preventing a host flow from accidentally publishing the prior file. Logout now returns 503 when server-side session revocation fails while still clearing the current browser cookie.
- Prior questionnaire versions can be loaded as candidates and must pass the normal checker, compatibility acknowledgement, preview, and explicit publish confirmation before going live.
- Login throttling now reserves hashed per-IP attempts atomically before password verification, so concurrent guesses cannot race the previous count-then-insert check; a throttle-store outage fails closed.
- Candidate publication now displays checker warning/note details, gates and signs the full KQA700–KQA710 compatibility set, and prevents restore from replacing an active candidate without canceling it first.
- `analyze_answers` rejects blank or overlong question selectors before reading respondent data. Authenticated password changes reserve five hashed per-account attempts per 15 minutes before scrypt verification and fail closed if the shared limiter is unavailable.
- Workspace owners can transfer ownership to an existing member through an explicit confirmation; the former owner becomes an admin. Owners can also promote or demote existing non-owners, with membership-epoch fencing and transactional audit events.
- New interviews can be built in-app for single choice, checkboxes, dropdown, full-order ranking, short and long text, number, scale, date, and bounded repeatable records. Repeat groups support up to 12 typed fields and explicit minimum/maximum row bounds. Hosts can add and reorder sections, assign questions, edit stable section metadata, and choose the full-page, section-by-section, or one-question-at-a-time flow. Up to 20 AND-combined routing rules can show a later question based on earlier answers' presence, choice, numeric value, scale value, or date. OR routing remains on the HTML authoring path. Hosts can allow optional comments, set minimum/maximum checkbox selections, set text length limits, and specify numeric increments. The composer generates bounded, escaped portable HTML and sends it through the existing checker, live probe, and create gate; custom controls and live-version edits stay on the reviewed HTML path. Ranking enforces KQA's 2–8 option bound and preserves full-permutation semantics.
- Interview creation now atomically stores the open interview, initial version, default single-mode participant, and creation event. Host name/status edits, questionnaire publication, profile changes, and single-to-multi promotion during participant addition write their audit events in the same transaction as the mutation; an audit-store failure aborts the change.
- Host error toasts now use assertive alert semantics and remain visible twice as long as success toasts; success messages retain polite status semantics.
- Successful MCP `create_interview` responses now include static-check diagnostics as well as counts, so hosts can see warnings in context instead of receiving a count only.
- Host mutation origin checks now compare normalized host and scheme using the trusted forwarded protocol, and fail closed when the protocol is absent or unsupported.

## Ranked remaining gaps

| Priority | Gap | Impact | Recommended next step |
| --- | --- | --- | --- |
| P1 | **Outbound mail reconciliation is partial.** Participant and workspace sends persist Message-IDs before SMTP and suppress silent token rotation/retry. Hosts can perform rate-limited IMAP checks for exact stored IDs. Attempts without a matching delivery-status notice can remain unknown indefinitely. | Hosts still need a duplicate-risk decision for an ambiguous participant invite; an IMAP status check cannot prove delivery when the mailbox has no matching notice. | Add provider delivery webhooks or an explicit host resolution workflow for pending attempts, with audit history and duplicate-send warnings. |
| P1 | **MCP write outcomes can be ambiguous across the connected tool bridge.** In two live production probes, `create_interview` returned a generic server error even though the interview, initial version, default person, and creation event had committed. Listing reconciled the first disposable interview; the second was reconciled, its single-to-multi addition and event were verified, then it was deleted and confirmed absent. The source tool does not accept a caller idempotency key. | A client that retries a failed-looking create or add-people call can produce duplicates. The observed failure may be in the connector response path; its exact boundary is not isolated yet. | Trace the connected bridge's timeout/response handling, and add persisted operation idempotency or a first-class result-reconciliation path for non-idempotent writes. |
| P1 | **Exports lack point-in-time snapshot semantics, and buffered generation still materializes whole files.** Buffered outputs are capped at 16 MiB and streamed host CSV at 64 MiB; source payload and streamed-page reads are capped at 8 MiB. MCP text avoids duplicating larger payloads, while the structured response still contains the full file. A changing interview can be modified during a multi-page download, and a buffered serializer can allocate beyond the response cap before it rejects the result. | Export rows can reflect concurrent edits and buffered generation can use more memory than the final output limit. | Establish snapshot semantics; consider streaming or background artifacts for buffered formats and a transport that avoids materializing large MCP file results. |
| P2 | **The workspace asset quota is a fixed application-wide value.** Each workspace has 100 MiB, enforced transactionally. Owners can see usage and delete assets, but cannot configure a different ceiling to match their plan or policy. Publication, preview-draft saves, and deletion still coordinate transactionally to prevent dangling image URLs. | Workspaces with different needs have the same capacity, and plan-based storage tiers are not supported. | Add a tenant-scoped owner setting if product plans require variable storage, with a clear migration policy for existing workspaces above a lowered ceiling. |
| P1 | **Consent, retention, and withdrawal rely on host procedures.** The app stores person-linked answers and supports manual deletion, but it does not manage notice versions, consent records, retention windows, or respondent withdrawal. | Hosts can collect data without a consistent in-product record of the notice or planned deletion. | Design a versioned notice and optional consent gate, plus workspace-configured retention, dry-run review, audited deletion, and a respondent withdrawal route. Avoid legal defaults; make policy owner-configurable. |
| P2 | **Workspace and account closure are incomplete.** Ownership transfer and owner-controlled admin/member role changes are available, but workspace closure and self-service account deletion are not. | A workspace or account cannot be closed through a complete reviewed workflow. | Add reviewed workspace/account closure with explicit data-retention, audit, and cascade behavior. |
| P2 | **The connected KQA `list_people` tool cannot continue its returned cursor.** The exposed tool accepts only `interviewId`, although the server returns `nextCursor` and supports `cursor`/`limit`. A 51-person disposable interview returned the same 50 person IDs on a repeated connected-tool call with the cursor supplied. | Hosts using this connected tool surface can repeatedly read only the newest 50 people; the app's own MCP endpoint has cursor support. | Expose `cursor` and `limit` in the connected-tool schema and verify that consecutive calls return disjoint pages through the final row. |
| P2 | **The in-app questionnaire composer does not support all advanced authoring.** It supports the common scalar and repeat types, all three presentation modes, sections, optional notes, input bounds, and up to 20 AND-combined earlier-answer conditions, including typed numeric, scale, and date comparisons. OR conditions, custom controls, and editing existing versions remain on the HTML workflow. | Hosts still need format knowledge for advanced questionnaire behavior, and there is no visual edit path that can preserve a live version's IDs and present compatibility changes. | Add OR composition only with a clear bounded UI; later add stable-ID import/editing behind the existing version preview, compatibility gate, and explicit publish review. |
| P2 | **Campaign operations are mostly manual.** Hosts refresh progress and resend/check invitations manually; there are no scheduled reminders or completion notifications. | Follow-up work and response monitoring do not scale well across larger cohorts. | Add optional close dates, rate-limited reminders for eligible non-submitters, and owner-configured completion/failure notifications with audit history. |
| P2 | **Recovery assurance is not verifiable in the repository.** Tenant migration requires backup confirmation, but there is no documented restore drill or tested recovery objective. | A correct backup schedule is not proof that data can be restored in time. | Document the configured backup schedule/retention, define RPO/RTO, and run a periodic restore exercise with evidence. |
| P2 | **Cold-start database setup still includes data migration and DDL work.** Index setup can scan and deduplicate pending-signup records when a unique index is absent, while each new serverless isolate may repeat the scan and index setup. | A large legacy collection can increase cold-start latency and memory during scale-out; the runtime database credential also needs index and data-cleanup privileges. | Move data cleanup into a bounded, resumable migration with progress/locking; leave runtime index checks lightweight and use a narrower runtime database role. |
| P2 | **Tenant backfill only supports the Axion legacy transition.** The operation is owner-only, checks backup attestation and ownership links, serializes runs with an expiring lease, records per-collection checkpoints, and verifies after idempotent missing-tenant updates. | Other future tenant migrations need a general migration framework, and the app cannot verify that an attested database backup is restorable. | Keep this path limited to the reviewed Axion assignment; build a versioned migration framework and restore drill before broader ownership changes. |
| P2 | **Analytics can be vulnerable to repeated small-cohort comparisons.** Small cells are currently part of the product contract and are disclosed; repeated filtering can still enable differencing. | Results may reveal information about individual respondents in small cohorts. | Decide on a workspace-level disclosure policy (minimum cell size, query budget, suppression or approved exceptions), then apply it consistently in UI and CSV. |
| P2 | **Database connection limits are per warm isolate.** The Mongo pool cap does not itself cap aggregate connections across serverless instances. | Bursts can exceed the database connection budget even when each function instance is within its own cap. | Measure concurrent-instance behavior and set a total connection budget or serverless connection policy. |
